## 1. 产品概述

### 1.1 一句话定位

「吃了没」是一个**无广告、界面极简、下单快、配送透明**的外卖点餐 App，让用户从「打开 App」到「吃上饭」的每一步都干净、确定、不被打扰。

### 1.2 背景与问题

以美团为代表的主流外卖 App 存在以下体验问题：

- **广告与营销位多**：开屏广告、信息流推广、弹窗红包，干扰决策；
- **价格不透明**：结算前难以看清配送费、包装费、优惠构成，容易「最后一步加价」；
- **推荐不精准**：千人千面算法偏向平台利益，用户反复划不到想吃的；
- **忌口不友好**：用户不想吃辣/香菜/猪肉时，只能进店后逐道甄别；
- **不喜欢的店无法避开**：拉黑一家店后，它依然反复出现在推荐流里。

### 1.3 产品价值主张

1. **零广告零弹窗**：首页只做「帮用户更快吃上饭」这一件事；
2. **价格透明明细**：小计、配送费、优惠、合计一目了然，标注「无隐藏费用」；
3. **千人千面忌口**：点餐前先选「这一顿不想吃什么」，系统自动过滤相关菜品并写入订单备注；
4. **拉黑店铺**：拉黑后店铺从推荐、搜索、列表中彻底消失；
5. **配送透明**：预计送达倒计时 + 超时必赔承诺 + 骑手路线动画。

### 1.4 竞品差异化（vs 美团）

| 维度 | 美团 | 吃了没 |
| --- | --- | --- |
| 广告 | 开屏、信息流、弹窗 | 无广告、无弹窗 |
| 价格 | 结算易出现额外费用 | 全明细透明 + 「无隐藏费用」标识 |
| 推荐 | 平台利益导向 | 时段 + 历史口味 + 收藏加权 |
| 忌口 | 需逐道甄别 | 选忌口自动隐藏 + 自动写入备注 |
| 店铺管理 | 拉黑后仍出现在推荐 | 拉黑后彻底消失 |
| 配送承诺 | 部分准时宝 | 全单超时必赔（演示规则） |

## 2. 目标与成功指标

### 2.1 产品目标

- **V1 目标**：跑通「浏览 → 点餐 → 下单 → 支付 → 配送跟踪 → 再来一单」的完整用户闭环，并验证差异化体验。
- **长期目标**：成为「干净、透明、懂我」的外卖首选。

### 2.2 核心指标

- 北极星指标：**周活跃下单用户数**；
- 过程指标：浏览→下单转化率、平均下单时长、订单准时率；
- 体验指标：忌口功能使用率、拉黑功能使用率、店铺收藏率；
- 演示版验收指标：完整闭环可跑通、`npm run build` 零报错、无控制台错误。

## 3. 目标用户与核心场景

### 3.1 用户画像

| 画像 | 特征 | 核心诉求 |
| --- | --- | --- |
| 学生党 | 18-24 岁，预算敏感，爱尝鲜 | 便宜、快速、宿舍周边好店 |
| 年轻白领 | 25-32 岁，午晚餐刚需 | 不踩雷、按时送达、少被广告打扰 |
| 忌口/过敏人群 | 不吃辣、香菜、猪肉、海鲜等 | 快速筛掉不能吃的 |

### 3.2 核心场景

1. **午餐快速点**：中午 12 点，打开 App，看「现在适合吃」推荐，30 秒内下单；
2. **忌口筛选**：这顿不想吃辣和香菜，选完后菜单自动过滤，结算自动备注给商家；
3. **拉黑避雷**：上次点过一家很难吃的店，拉黑后它永远不再出现；
4. **配送透明**：下单后看得到骑手在哪、还有多久到，超时能看到赔付承诺。

### 3.3 用户故事

- 作为学生，我想在午休时快速点一份 25 分钟能到的饭，这样我能睡个午觉；
- 作为不吃辣的女生，我想在选餐时一次筛掉所有辣菜，而不是逐道看描述；
- 作为被某家店坑过的用户，我想把它拉黑，让推荐流里不再出现它；
- 作为白领，我想在下单前看清配送费和优惠，不想最后一步才看到隐藏费用。

## 4. 产品范围

### 4.1 V1 包含（用户端完整闭环）

- 首页：搜索、时段推荐、猜你喜欢、分类筛选、附近好店排序；
- 店铺：菜单分组、菜品标签、售罄置灰、加购、购物车抽屉；
- 结算：地址选择/新增、备注、忌口、价格透明明细、新人立减、满 30 免配送费；
- 支付：微信/支付宝/银行卡模拟支付；
- 配送跟踪：状态时间轴、模拟地图骑手动画、ETA 倒计时、超时必赔、联系骑手（演示）；
- 订单：历史列表、订单详情、一键再来一单；
- 我的：昵称、地址管理、收藏店铺、已拉黑店铺；
- 个性化：这一顿忌口（12 种）、拉黑店铺、主题色（6 套方案实时切换）；
- 部署：GitHub Pages 免费托管 + 推送自动部署。

### 4.2 V2 新增（对标市面外卖 App 补齐）

- 优惠券：领券中心、我的优惠券（可用/已用/过期）、结算自动匹配最优券、下单核销、取消订单返还；
- 评价：送达后可评（星级+标签+文字）、店铺评价墙（聚合评分 + 星级分布 + 列表）、服务端同步；
- 订单动作：下单 15 秒内可取消（演示退款）、配送中可催单（演示加速）；
- 菜品规格：规格弹层选择、同一菜品多规格独立计价、订单快照与再来一单还原；
- 店铺满减：多档满减自动取最优档，结算明细单独展示；
- 营业时间：营业中/休息中角标、打烊禁下单、商家信息卡（地址/资质/营业时间）；
- 搜索体验：热搜词 + 搜索历史联想；列表筛选（免配送费/有满减/评分≥4.5）；
- 餐具偏好：按需/不要餐具/1 套，随订单记录。

### 4.3 V2 暂不包含

- 真实支付、真实地图、真实商家/骑手数据；
- 商家端、骑手端、多人拼单、评价晒图、会员体系、消息中心；
- 真实支付与地图（当前为模拟实现）。

## 6. 业务流程

### 6.1 下单主流程

```text
打开首页
  → 搜索/推荐/分类找到店铺
  → 进入店铺，选「这一顿不想吃什么」（可选）
  → 加购菜品（未达起送不可结算）
  → 结算：选地址 → 确认备注与忌口 → 查看价格明细
  → 提交订单 → 模拟支付 → 支付成功
  → 配送跟踪：备餐 → 骑手取餐 → 配送中 → 已送达
  → 订单列表/详情 → 再来一单
```

### 6.2 订单状态机

状态：`已支付 → 商家备餐 → 骑手取餐 → 配送中 → 已送达`

演示时间轴（相对下单时间）：备餐 0s → 取餐 18s → 配送 40s → 送达 80s；状态按下单时间戳实时推导，刷新安全。

| 实体 | 关键字段 |

## 11. 验收标准

### 11.1 主流程验收

1. 首页 → 店铺 → 加购 → 结算 → 支付 → 配送跟踪 → 送达 → 订单列表 → 再来一单，全链路可走通；
2. `npm run build` 零报错；浏览器 console 无报错；
3. 刷新后购物车、订单、配送进度、偏好设置均保留。

### 11.2 边界验收

- 空购物车不可结算；未达起送按钮禁用；
- 售罄菜品不可加购；不存在订单/店铺有兜底页；
- 删除地址前二次确认；清空购物车前二次确认；
- 拉黑后首页/推荐/搜索不再出现，取消后恢复；
- 忌口选择后菜单隐藏数量正确，备注写入「忌口：…」。

- 演示模式（后端不可用）时数据仅存本机，换设备/清缓存会丢失；登录后可云端同步订单、偏好、优惠券、评价；
- 配送时间轴为演示加速（80 秒完成一单），真实场景需接入真实配送数据。
