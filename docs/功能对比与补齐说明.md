## 2. 每个功能的设计逻辑

### 2.1 优惠券（领券中心 + 我的优惠券）

- **领券中心**：内置 4 张全场通用券（满 15 减 3 / 满 20 减 5 / 满 40 减 8 / 满 60 减 15），领取后生成 7 天有效期；
- **我的优惠券**：按「可用 / 已用 / 已过期」三态展示，避免用户以为券还能用；
- **结算自动匹配**：进入结算页后，系统自动选中「门槛满足且抵扣最大」的券，用户也可以手动切换或不用；
- **核销**：下单成功即标记已用，取消订单时自动返还，保证券不凭空消失也不被重复使用；
- **逻辑要点**：券的使用门槛按**商品小计**判断（与主流 App 一致），满减与优惠券可叠加，但实付最低不为负数。

### 2.2 评价（送达后可评 + 店铺评价墙）

- **评价时机**：订单送达后才能评价，一单一评（防刷）；
- **评价内容**：星级（1-5）+ 标签多选（味道好/分量足/包装好/送达快/值得回购/口味一般…）+ 文字；
- **店铺评价墙**：店铺详情新增「评价」Tab，展示聚合评分、5 星到 1 星分布条、好评率、评价列表；
- **评分聚合逻辑**：店铺评分 = 该店全部评价（种子评价 + 用户评价）的平均分，保留 1 位小数；种子评价保证新店也有口碑内容可看；
- **同步**：登录后评价写入服务端，换设备也能看到自己和他人的评价。

### 2.3 取消订单 / 催单

- **取消**：下单后 15 秒内（对应「商家备餐前」）可取消，取消后状态变为「已取消」并展示退款文案；演示环境按原路退回，在线模式会返还优惠券；
- **催单**：配送中任意时刻可「催一催」，每次催单让演示配送进度提前 8 秒（最多 3 次），刷新后进度不倒退；
- **为什么这样做**：真实外卖里「取消」和「催单」是最高频的售后动作，v2 用时间窗口 + 幂等状态机把它们做成可演示、可测试的闭环。

### 2.4 菜品规格

- 有规格的菜（如奶茶的杯型/冰量、汉堡的辣度/芝士、沙拉的加料）加购前先弹**规格选择层**；
- 同一道菜不同规格在购物车里是**独立条目**，单价 = 基础价 + 规格加价（如中杯 -3 元、加鸡胸 +8 元）；
- 下单时把规格写进订单快照（`大杯 · 少冰`），「再来一单」能原样还原，不会丢规格。

### 2.5 满减活动

- 每家店可配置多档满减（如奶茶店：满 20 减 3、满 35 减 7）；
- 结算时**自动应用金额最大的一档**（小计 ≥ 门槛），价格明细里单独一行展示「店铺满减」；
- 前后端共用同一套计价函数（`src/utils/pricing.ts`），演示模式与在线模式价格一致，服务端以数据库价格二次计算防止改价。

### 2.6 营业时间与打烊

- 每家店配置营业时间（支持跨天，如烧烤 16:00-02:00）；
- 首页卡片显示「营业中 / 休息中」角标；打烊店铺详情页显示红色横幅，菜品不能加购、购物车不能结算；
- 逻辑：**展示真实运营状态**，避免演示时出现「打烊店还能下单」的常识 bug。

### 2.7 商家信息卡

- 店铺详情展示营业时间、商家地址、资质（营业执照 / 食品经营许可证 / 清真认证），补齐了主流 App「商家信息」入口的信息量。

### 2.8 搜索历史 / 热搜

- 搜索框聚焦时弹出「热搜」+「搜索历史」，点击或回车即搜索；
- 历史去重、最多保留 8 条、存 localStorage，关掉页面再回来还在；
- 逻辑：减少重复输入，是外卖搜索的标准交互。

### 2.9 列表筛选

- 「附近好店」新增筛选 chips：免配送费 / 有满减 / 评分≥4.5，可多选，与关键词、分类、排序叠加生效。

### 2.10 餐具偏好

- 结算页可选择「按需 / 不要餐具 / 1 套」，随订单写入并展示；「不要餐具」带 🌱 标识，呼应环保。

## 3. 计价规则（透明化）

```text
商品小计 = Σ(菜品单价 × 数量)，单价含规格加价
店铺满减 = 小计满足门槛的最大一档（自动）
优惠券   = 用户所选券（门槛按商品小计，与满减可叠加）
新人立减 = 首单 -5 元
免配送费 = 商品小计 ≥ 30 元（或店铺免配送费）
实付     = max(0, 小计 + 实付配送费 - 满减 - 券 - 立减)
```

所有行项目在结算页逐条展示，并保留「无隐藏费用」标识。
